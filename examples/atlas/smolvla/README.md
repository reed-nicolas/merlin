# SmolVLA flow-loss forward

This example takes the SmolVLA flow-matching loss forward (`lerobot/smolvla_base`, `atlas_v1_awq_tile_static`, one camera, fixture case 0) from [atlas-torchao](https://github.com/ucb-ee290c/atlas-torchao) through the same route as the TinyLlama whole-model example: a live capture through model2MLIR's `atlas_fp8` adapter, `stage-capture`, and `native-compile --application`. Codes, exponents, and ordinary parameters come unchanged from the export.

Create the bundle with atlas-torchao's own commands (`docs/algos/howto-model-to-fx-graph.md`, section 8): `eval_policy.py --export-only --algo atlas_v1_awq_tile_static`, then `fx_export.py --boundary smolvla_flow_loss --n-images 1`, then `scripts/tile_flow/verify_bundle.py`. The loader reads the export for the weights and the bundle's `fx/` only for its recorded fixture inputs; it never loads the saved graph.

The captured graph is not the bundle's graph. `adapter_loader.py` rebuilds the policy from the raw export as `fx_export.py` does, then edits the module before handing `fx_export.SmolVLAFlowLoss` to `atlas_mlir_native.capture.prepare_model`, which re-exports it under the adapter. The edits are: decoded weights become payload-free placeholders; the four `rotary_emb` inverse-frequency buffers, which the export does not carry and SmolVLA's own rotary never reads, are deleted; the quantized `lm_head`, which the bundle declares uncalled, is detached; and the vision embedding's forward is replaced to use precomputed position ids. A strict re-export fails if a deleted or detached object is read.

The position-id replacement needs care. SmolVLM's vision tower builds an all-true patch mask for its fixed image size, so its position ids depend on no input, but exported directly they have a data-dependent extent. The loader computes them once with the unchanged module (they equal `arange(1024)`), binds them as one constant, and checks the embedding output and the whole boundary output bit for bit against the module without this replacement on the selected inputs before capture.

The adapter then rewrites native tails into ordinary nodes: each biased `atlas::qlinear` becomes the bias-free contraction plus an addition, the `atlas::qconv2d` becomes a bias-free `atlas::qlinear` plus the reshape, permute, and bias addition of its definition, and the non-overlapping patch `im2col` becomes a reshape and permute. The manifest lists every rewrite.

Set `ATLAS_EXPORT_DIR`, `ATLAS_FX_BUNDLE`, `ATLAS_EXPECTED_CONTRACT_SHA256`, and `ATLAS_EXPECTED_POLICY_SHA256`, optionally `ATLAS_FIXTURE_CASE` and `ATLAS_SOURCE_OUT` (which receives `inputs.safetensors` and `source.json`), then run the capture worker from the whole-model README with `--loader examples/atlas/smolvla/adapter_loader.py`. The interpreter needs lerobot 0.6.1 with torchvision and the `atlas_fp8` adapter installed.

Select the precision policy with `select_policy.py`. It needs the MPFR constant-power helper (`merlin targetgen native-math-build --out DIR`, which writes `manifest.json` with the helper's policy; export `MERLIN_CONSTANT_MATH_HELPER` to the built library for compilation) and the host trig policy from `host-math/` (see its README). Then stage and compile as in the whole-model README, and package with `host-math/prepare_smolvla_execution.py`.

`reference/flowloss_reference.py` is an independent reference for the expected output words. It interprets the bundle's saved `fx/model.pt2` node by node with the selected policies' arithmetic, applying the adapter rewrites above as bodies, and refuses any value outside a selected policy domain. `reference/test_smolvla_primitives.py` checks its primitives against IEEE and MPFR results.
