# SmolVLA host unary math

SmolVLA's host trig follows the TinyLlama rotary pattern in `../../rotary-host`, generalized to two source types. Binary32 `sinf`/`cosf` evaluate the rotary angles of lerobot 0.6.1 `apply_rope`, and binary64 `sin`/`cos` evaluate the flow-matching timestep embedding of `create_sinusoidal_pos_embedding`. Nothing here is Atlas computation.

The archive is built from unmodified CORE-MATH revision `a055b9b9a86b857e49573e339cf68306ad92c831`: the binary32 `sinf.c`/`cosf.c` already vendored for TinyLlama and the binary64 `src/binary64/sin/sin.c` and `src/binary64/cos/cos.c` vendored beside them in `../../rotary-host/third_party/core-math`. A small wrapper exports `cos`, `cosf`, `sin`, and `sinf`. The RV64GC/lp64d flags, the x86-64-v3 execution-host flags, and the deterministic archive steps match the TinyLlama build; implicit contraction is off, explicit upstream FMA stays fused, and flags and errno are unobserved.

The declared domains come from the captured source arithmetic, which `scripts/domains.py` states exactly. Binary32: `f32(p) / pow(10000, f32(j) * 0.03125)` (division, not an inverse-frequency multiply) for every integer position `p` in 0..511 and `j` in 0..31, which covers the batch-1 flow-loss positions 0..162. Binary64: `scaling[k] * f64(t)` for `k` in 0..359 and every binary32 time `t = f32(k/1000)`, `k` in 0..1000, which includes the fixture times 0.25 and 0.75. Two scaling vectors are declared because they differ in 36 lanes: torch eager arithmetic, and the captured MLIR chain (decomposed linspace, constant `pow` folded correctly rounded by Merlin's MPFR helper).

With `RISCV` set to the pinned toolchain prefix, `MERLIN_CONSTANT_MATH_HELPER` set, `PYTHON` set to the compiler interpreter with Merlin on `PYTHONPATH`, and `HOST_MATH_OUT` naming the output directory, run `bash scripts/run_host_math_gate.sh`. It writes the domain, builds both archives with receipts, runs the probe under the existing Spike/pk and natively, and compares every row bitwise. It then checks each distinct result against correctly rounded MPFR through `MathHelper.unary_reference` and writes `host-unary-math-policy.json` for the `host_unary_math` field of the precision policy. Each step fails closed.

For functional validation, package a compiled SmolVLA application with `prepare_smolvla_execution.py`, which takes the arguments of `../../whole-model/unchanged_fx/prepare_live_execution.py` and binds the `execution_host_math` name to `execution_host_math_smolvla.py`. Pass `--functional-validation`, `--execution-host-math-archive $HOST_MATH_OUT/execution-host-math/libcore-math-smolvla-execution-host.a`, `--execution-host-math-equivalence $HOST_MATH_OUT/execution-host-math/equivalence-receipt.json`, and `--execution-host-math-rv64-output $HOST_MATH_OUT/rv64-host-math.bin`. Each selected unary component is replaced in a separate runtime copy only after the receipts, archive pins, and component text match, and the replacement refuses any input outside the qualified angle sets before writing.

The component validation and replacement are shared with TinyLlama through `replace_unary_components` in `execution_host_math.py`; TinyLlama packages stay byte-identical. This is functional validation only and confers no deployment qualification. Framework equivalence is not claimed: torch CPU binary32 trig differs from the correctly rounded results at some rotary angles, while its binary64 results agree after the graph's binary32 cast over the declared domain.

Run the tests with `python -m pytest -q test_execution_host_math_smolvla.py` from this directory, with Merlin's `src` and the unchanged_fx directory on `PYTHONPATH`. The real tiny-application test packages Merlin-emitted f32 and f64 unary regions through the unchanged packager, links the generated execution archive, and compares outputs to the RV64 probe; it skips unless `HOST_MATH_OUT` holds the generated evidence.
