## First C-library integration contract

The first contract is dense row-major `A[M,K]: int8`, `B[K,N]: int8` → `C[M,N]: int32` matmul, with no bias, activation, transpose or requantization. The TVM fork implements its external C ABI, opt-in Relax lowering and a cross-compiled Gemmini C-library adapter. The adapter checks signed widths, scale types, resource geometry and full accumulator readout; a different arithmetic target requires its own numerical contract and reference. Numerical execution of this separate adapter passes the pinned functional simulator; this does not qualify a complete TVM graph or deployed hardware.

The [TVM integration guide](https://github.com/reed-nicolas/tvm/blob/58bad17e55c8bab37db2126acbe286cb08480a5f/apps/gemmini/README.md#external-matmul-compiler-boundary) documents the pass and its host test command. Eleven tests pass with an explicitly linked test-only C reference, including bytecode/compiled export/reload, rectangular and extreme inputs, repeated calls, mixed external/CPU operations, preserved control flow and errors. Admission requires positive static rank-two shapes and `K <= 131071` so all signed-int8 products and sums fit int32. Unsupported calls stay on the normal host path. This does not quantize or offload the current FP32 ResNet graph, implement Gemmini scheduling or establish a target runtime. Run the pass before `LegalizeOps` and use a CPU compilation target.

The whole-matmul reference adapter uses the C library's output-stationary `tiled_matmul`, null bias, identity scales, `NO_ACTIVATION`, `full_C=true` and `low_D=false`. Fixed one-array tiles limit each internal reduction to 16 products: the provisional hardware's 20-bit PE output could overflow under larger automatic K tiling, even though its accumulator SRAM is int32. Outer K tiles accumulate in int32. This conservative reference path passes bounded functional validation; the TVM-owned primitive schedule path is described below, while target timing remains pending. WS matmul/convolution FSM paths are prohibited. The new static groups=1 integer convolution decomposition uses CPU packing/restoration around the existing TVM-scheduled primitive matmul.

The provisional source set uses Gemmini `6ad65b90`, its gemmini-rocc-tests gitlink `7c540b3a` and libgemmini gitlink `ea8f7ed7`. Its integer parameter header has SHA256 `3758ae967af3a179497660970201093a7fb624be00173990ce33d3f5c38da924`, 16×16 geometry, 256-KiB scratchpad and 64-KiB accumulator. The build verifier stages exact Git blobs into the build directory, verifies resolved includes and leaves reference checkouts unchanged. The live hardware checkout's floating-point parameter header is incompatible and is not used. A matching current FireSim deployment is still unconfirmed.

The library's CPU branch does not support `full_C`: it warns and continues through an element-width output cast. Use an independent bounded int64 reference for expected integer results. Cover negative operands, rectangular shapes, padded strides, partial array tiles and K accumulation across tiles. The accelerator path emits a final fence, but completion, compiler ordering and memory visibility still need validation on the chosen runtime. Source inspection does not establish those execution properties.

The optimized path now exposes library primitives to TVM-owned tensor schedules and integrates generated graph calls. `prepare_gemmini_graph` folds constants before device lowering, preserves the Gemmini schedule and fuses surrounding CPU operations. Baseline and optimized baremetal fixtures pass exact functional simulation, with fewer calls and less workspace after fusion. The exporter rejects unsupported host workspace callbacks. Kernels 1/3/7 now pass a bounded convolution/residual/requantization graph in matched Spike, including raw-output checks, retained outputs and no-FSM/failure controls. Tensor-memory preflight covers explicit packing and residual lifetimes; full-model quantization and capacity remain unqualified. Actual-platform completion/visibility remains unqualified.

## Provisional target checks

From the comparison checkout, with Python and PyYAML available:

```sh
python examples/gemmini/comparisons/tvm/check_target.py --config examples/gemmini/comparisons/tvm/target.yaml
PYTHONPATH=src python merlin/tests/gemmini/test_tvm_target.py
```

The checker rejects incompatible arithmetic declarations, any hardware-loop allowance or WS selection, invalid address ranges, overlapping reservations and requests larger than a declared confirmed capacity. Source identities are syntax-checked declarations; the [adapter build verifier](https://github.com/reed-nicolas/tvm/blob/58bad17e55c8bab37db2126acbe286cb08480a5f/apps/gemmini/README.md#pinned-c-library-adapter) separately verifies the selected header bytes and actual compiler includes. Successful configuration checks always leave `paper_ready` and `deployment_qualified` false.

The [baremetal CPU proof](https://github.com/reed-nicolas/tvm/blob/58bad17e55c8bab37db2126acbe286cb08480a5f/apps/gemmini/README.md#bounded-baremetal-cpu-proof) independently runs a small TVM-generated graph under generic Spike without a guest C++ runtime or heap. Its explicit constant, workspace and stack reservations can be checked through this interface. It does not execute Gemmini or qualify complete models. Jack confirms default Gemmini with a Rocket host; the exact FireSim build and usable guest DRAM remain unresolved.

Optionally pass `--memory-plan /path/to/reservations.json`. The JSON contains a `regions` list of disjoint coarse reservations, each with `name`, integer `address` and integer `size_bytes`. Account for code/static data, weights, arena/workspace, stack and other runtime storage; do not list allocations inside an arena as overlapping top-level regions. For example, `{"regions":[{"name":"code_and_static","address":2147483648,"size_bytes":1048576}]}` reserves the first MiB only. Unreserved bytes are a gap in supplied reservations, not measured free memory. This interface does not discover omitted allocations or allocator peaks. Unknown board capacity stays unknown even when all supplied ranges fit the requested map; the 8-GiB request is a planning assumption, and the small generic-Spike probe can use a separate 256-MiB map.

Keep compiler lowering, hardware configuration, runtime, quantization/calibration, model inputs and measurement boundaries explicit for each compared implementation. Full checkpoint and input provenance, host fallback coverage and numerical thresholds must be selected before execution. Declare tuning workloads and budgets explicitly; normal shape specialization and TVM schedule tuning are permitted. Keep baseline internals and held-out answers out of the evaluated Merlin compiler-generation loop; partial models or isolated stages remain diagnostics.

A future thin TVM adapter belongs at `packages/merlin-analysis/src/merlin/baselines/tvm_gemmini.py`, with target choices supplied by configuration and substantive lowering/runtime integration owned by the TVM fork. No placeholder module is supplied. Captures, weights, binaries and receipts belong beneath the configured `out/` roots, not here. Do not infer compatibility or qualification from repository checkout or branch setup.

## Pinned functional simulator

[build_simulator.py](build_simulator.py) stages the exact integer `libgemmini` sources from existing Git objects, compiles against the selected installed Spike headers, and checks explicit plugin loading with a known CPU-only ELF. It changes no reference checkout and records source/tool/dependency hashes. The load check does not execute a Gemmini numerical workload.

```sh
python examples/gemmini/comparisons/tvm/build_simulator.py --libgemmini-repo "$LIBGEMMINI_REPO" --spike-prefix "$SPIKE_PREFIX" \
  --cxx "$HOST_CXX" --runtime-lib-dir "$SPIKE_SUPPORT/lib" --runtime-bin-dir "$SPIKE_SUPPORT/bin" \
  --smoke-elf "$CPU_PROOF/model.elf" --build-root "$BUILD_ROOT" --output-dir "$BUILD_ROOT/simulator-check"
python "$TVM_ROOT/apps/gemmini/verify_matmul_runtime.py" --adapter-receipt "$ADAPTER_BUILD/receipt.json" --simulator-receipt "$BUILD_ROOT/simulator-check/receipt.json" \
  --riscv-gcc "$RISCV_BIN/riscv64-unknown-elf-gcc" --spike "$SPIKE_PREFIX/bin/spike" --dtc "$SPIKE_SUPPORT/bin/dtc" \
  --spike-library-dir "$SPIKE_SUPPORT/lib" --plugin "$BUILD_ROOT/simulator-check/libgemmini.so" --output-dir "$BUILD_ROOT/matmul-runtime-check"
```

Set the paths to existing selected installations and passing adapter/CPU builds; both output directories must be fresh. The packaged numerical verifier passes 13 valid calls, 18 invalid cases, extreme reductions, tails/strides, repeated-call recovery, buffer guards and intentional failure controls. It rechecks immutable bindings and audits the final ELFs for FSM instructions. These results cover the provisional functional model only, with no timing, actual-platform coherence or full-model qualification claim.

The original [TVM paper](https://www.usenix.org/conference/osdi18/presentation/chen) combines graph optimization, tensor scheduling and learned search. The whole-matmul adapter is an integration/reference path. The optimized backend now preserves tensor semantics and composes library primitives within TVM-controlled schedules. Bounded learned search uses actual TVM features and XGBoost, with candidate/build identities and separate semantic/device gates. Diagnostic labels verify machinery only; genuine target tuning and full-model evidence are still required for the complete paper methodology.
